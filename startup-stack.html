A startup playbook on free tiers

Zero to first customers

Fifteen steps, in the order you'll take them. Each one names the exact service to use, why it's the right pick, how to set it up, and what it costs now and later.

Part 1

Build

Get a real product live on your own domain.

01

Start the repo

GitHubgithub.com

Everything starts as code in one private repo. GitHub is where your code lives, where tests run on every push, and where you track what to build next.

  • Repositories
  • Actions
  • Issues
  • Projects

How to set it up

  1. Create a private repo: gh repo create my-app --private --clone.
  2. Protect main in Settings → Branches so every change goes through a pull request.
  3. Add .github/workflows/ci.yml to run lint, type-check and tests on each pull request.
  4. Use Issues for every bug and idea, and one Projects board (Backlog → Doing → Done) as your roadmap.
Free
Unlimited private repos, 2,000 Actions minutes/mo
When you grow
Team $4/user/mo
02

Claim your name

Cloudflare Registrar + DNScloudflare.com/products/registrar

Your domain is your brand, so it belongs where the rest of your infrastructure lives. Cloudflare sells domains at cost and its DNS is free and fast. Email Routing gives you hello@yourdomain without paying for an inbox.

  • Registrar
  • DNS
  • Email Routing

How to set it up

  1. Buy the domain in Cloudflare, or transfer it from GoDaddy: unlock it there, copy the auth code, then go to Domain Registration → Transfer. Transfers only work 60+ days after registration.
  2. Leave DNS on Cloudflare. Every later step adds its records here.
  3. Turn on Email → Email Routing and forward hello@ and founders@ to your personal Gmail.
Free
DNS and Email Routing free
When you grow
~$10/yr for a .com, at cost
03

Ship it

Cloudflare Workersworkers.cloudflare.com

Workers runs your app on Cloudflare's network in 300+ cities, and the free plan allows commercial use. Every push deploys automatically, and every pull request gets its own preview URL.

  • Workers
  • Workers Builds
  • R2
  • Turnstile

How to set it up

  1. Scaffold a Next.js app for Workers: npm create cloudflare@latest my-app -- --framework=next.
  2. In the dashboard, connect the GitHub repo under Workers Builds so pushes to main deploy to production.
  3. Attach your domain under the Worker's Settings → Domains & Routes.
  4. Store uploads in R2: npx wrangler r2 bucket create uploads, then bind it in wrangler.jsonc.
  5. Put a Turnstile widget on sign-up and contact forms to block bots without a CAPTCHA.
Free
100k requests/day, 10 GB R2
When you grow
Workers Paid $5/mo
04

Store the data

Neonneon.com

Your data lives in plain Postgres, so you can move it anywhere later. Neon sleeps when idle, which keeps it free, and branching gives every pull request its own copy of the database.

  • Serverless Postgres
  • Branching
  • GitHub integration

How to set it up

  1. Create a project in the region closest to your users and copy the pooled connection string.
  2. Save it as a secret: npx wrangler secret put DATABASE_URL.
  3. Query from Workers with @neondatabase/serverless and Drizzle ORM. Run drizzle-kit migrate in GitHub Actions.
  4. Install Neon's GitHub integration so each pull request gets its own database branch.
Free
0.5 GB, scales to zero
When you grow
Usage-based, from ~$5/mo
05

Let people in

WorkOS AuthKitworkos.com/authkit

AuthKit gives you hosted sign-up, sign-in, Google login and magic links free for up to a million users. When your first enterprise customer asks for SSO, you turn it on instead of rebuilding auth.

  • AuthKit
  • Social login
  • Magic Auth
  • Admin Portal (later)

How to set it up

  1. In the WorkOS dashboard, set up AuthKit and add https://yourdomain.com/callback as a redirect URI.
  2. Install @workos-inc/authkit-nextjs and set WORKOS_API_KEY, WORKOS_CLIENT_ID and WORKOS_COOKIE_PASSWORD as secrets.
  3. Add the AuthKit middleware to protect app routes, and enable Google and email magic links.
  4. On the first sign-in, create a matching user row in Neon keyed by the WorkOS user ID.
Free
Up to 1M monthly active users
When you grow
Enterprise SSO $125/connection/mo

Run

06

Talk to users

Resendresend.com

Every product needs to send email: a welcome, a password reset, a receipt, a product update. Resend handles all of it from one API, and its SMTP lets you reply from hello@yourdomain in Gmail.

  • Emails API
  • React Email
  • Broadcasts
  • SMTP

How to set it up

  1. Add a sending domain like mail.yourdomain.com. Resend can add the SPF and DKIM records to Cloudflare for you.
  2. Add a DMARC record in Cloudflare DNS: _dmarc TXT v=DMARC1; p=none;.
  3. Install resend and react-email, then send a welcome email from your sign-up handler.
  4. In Gmail, use Settings → Accounts → Send mail as, with smtp.resend.com, so replies come from hello@yourdomain.
  5. Use Broadcasts for a monthly product update to all users.
Free
3,000 emails/mo, 100/day
When you grow
Pro $20/mo for 50k
07

Watch what happens

PostHogposthog.com

You can't improve what you can't see. PostHog shows where users get stuck, lets you watch real sessions, and lets you release features to a few users first.

  • Product analytics
  • Session replay
  • Feature flags
  • Surveys

How to set it up

  1. Create a project and install posthog-js. Route it through your own domain with a small Worker proxy so ad blockers don't drop events.
  2. After sign-in, call posthog.identify() with the WorkOS user ID.
  3. Capture the moments that matter: signed_up, activated (the first real use), and upgraded.
  4. Build one funnel from sign-up to upgrade, and watch five session replays every week.
Free
1M events, 5k replays/mo
When you grow
Usage-based after that
08

Catch what breaks

Sentrysentry.io

Most users who hit a bug leave without telling you. Sentry catches the error, shows the exact line of code and the user it happened to, and alerts you.

  • Error monitoring
  • Source maps
  • Releases
  • Alerts

How to set it up

  1. Run npx @sentry/wizard@latest -i nextjs to add the SDK and config.
  2. Upload source maps in your GitHub Actions build so errors point to real lines of code.
  3. Tag each release with the commit SHA so you can see which deploy caused an error.
  4. Set an alert rule to email you on any new issue.
Free
1 user, 5k errors/mo
When you grow
Team $26/mo

09

Become a company

Stripe Atlas + Mercurystripe.com/atlas

Before you take money, you need a company and a bank account. Atlas forms a Delaware C-corp, the structure investors expect, and Mercury gives you a free business account.

  • Atlas
  • Mercury checking

How to set it up

  1. Apply on Stripe Atlas ($500). It files the incorporation, issues founder stock, files your 83(b) election and gets your EIN.
  2. Open a Mercury account with the Atlas documents and EIN.
  3. Set Mercury as Stripe's payout account, and keep all company spending on Mercury cards.
Free
Mercury is free
When you grow
Atlas $500 one-time, then ~$100/yr Delaware agent
10

Get paid

Stripestripe.com

Stripe turns your pricing page into revenue. Checkout takes the payment, Billing handles renewals, and the Customer Portal lets users upgrade or cancel without emailing you.

  • Checkout
  • Billing
  • Customer Portal
  • Webhooks
  • Tax

How to set it up

  1. Create your products and monthly or annual prices in the dashboard. Build everything in test mode first.
  2. From your Upgrade button, create a Checkout Session and redirect the user to it.
  3. Add a webhook at /api/stripe/webhook for checkout.session.completed and customer.subscription.updated / deleted, and update the user's plan in Neon.
  4. Link a Manage billing button to the Customer Portal.
  5. Test locally with stripe listen --forward-to localhost:8787/api/stripe/webhook, then switch to live keys.
Free
No monthly fee
When you grow
2.9% + 30¢ per card charge, Billing 0.7%

11

Get found

Google Search Consolesearch.google.com/search-console

People search for the problem before they know your product exists. Search Console shows which searches you appear for and whether Google can see your pages.

  • Performance report
  • Indexing
  • Sitemaps

How to set it up

  1. Add a Domain property and verify it with the TXT record in Cloudflare DNS.
  2. Submit https://yourdomain.com/sitemap.xml.
  3. Write one page for each problem your customers search for, and link them from your homepage.
  4. Every week, check Performance for queries where you rank on page 2 and improve those pages.

12

Make the content

Claude + Canvaclaude.ai

Building in public only works if you post every week, and blank pages kill that habit. Claude turns what you shipped into posts, threads and SEO pages in your voice. Canva turns them into images and short videos.

  • Claude Projects
  • Canva templates
  • Canva video editor

How to set it up

  1. In Claude, create a Project called Marketing. Add a one-page brand voice guide, your product notes and real customer quotes.
  2. Every Monday, paste the week's changelog and ask for 5 X posts, 2 LinkedIn posts and 1 short thread. Edit them so they sound like you.
  3. Use the same Project to draft one SEO page a week for a query you found in Search Console.
  4. In Canva, make three reusable templates: an announcement card, a screenshot frame and a customer quote card.
  5. Record a 60-second product demo and trim it in Canva's video editor. You'll reuse it on your homepage, social posts and the launch.
Free
Claude Free, Canva Free
When you grow
Claude Pro $20/mo, Canva Pro ~$15/mo
13

Build in public

Bufferbuffer.com

Early on, the founder is the marketing. Posting what you're building on X and LinkedIn builds an audience before launch. Buffer lets you write a week of posts in one sitting.

  • Publishing queue
  • Ideas
  • Analytics

How to set it up

  1. Connect X, LinkedIn and one more channel (Threads or Bluesky).
  2. Set two posting times per day on the queue.
  3. Every Monday, queue the posts and images you made with Claude and Canva across the week.
  4. Put UTM tags on links so PostHog shows which posts bring sign-ups.
Free
3 channels, 10 queued posts each
When you grow
Essentials $6/channel/mo
14

Launch

Product Hunt + Hacker Newsproducthunt.com

A launch week brings your first wave of users, backlinks and feedback all at once. It works best when a waitlist and your Buffer audience already know the date.

  • Product Hunt launch
  • Show HN
  • Resend waitlist

How to set it up

  1. Weeks before, add a waitlist form to your homepage that saves emails to a Resend audience. Email that list on launch day.
  2. Create your Product Hunt maker profile early and be active on other launches.
  3. Prepare a one-line tagline, 4 to 6 gallery images, a short demo video and a first comment explaining why you built it.
  4. Launch at 12:01 a.m. Pacific on a Tuesday to Thursday, then post and email your audience.
  5. Offer a launch-day discount with a Stripe coupon, and answer every comment that day.
  6. Later that week, post a Show HN on Hacker News and share the story in one or two subreddits where your customers already talk, following each one's rules.

15

Close the deals

HubSpot CRMhubspot.com/products/crm

Launches and posts bring in leads, and leads go cold if no one follows up. HubSpot keeps every person and deal in one place so nothing slips.

  • Contacts
  • Deals pipeline
  • Forms
  • Email tracking

How to set it up

  1. Create one pipeline: Lead → Demo → Trial → Paid → Lost.
  2. Connect your inbox, or BCC HubSpot, so every email is logged against the contact.
  3. Send new sign-ups to HubSpot from your sign-up handler using its contacts API.
  4. Every Friday, review open deals and follow up on anything quiet for a week.
Free
Unlimited users and contacts
When you grow
Starter ~$20/seat/mo
